# Чек-лист интерфейса Project Flow Agent

Выбирай пункты по экрану и критериям приёмки текущей фичи.

## Состояния и содержимое

- Для пустого списка сообщи, что отображается. Для недоступной заметки объясни причину, если она известна, и предложи применимое действие.
- Ошибка даты или отдельной записи сопровождается диагностикой. Покажи задачи, которые ядро смогло разобрать, в порядке исходной заметки.
- Длинные названия целиком читаются при переносе или доступны в полном виде при сокращении. Проверь реальную ширину вкладки со включёнными боковыми панелями.

## Доступность и тема

- Используй кнопки для действий и ссылки для переходов. Иконка-кнопка имеет доступное имя с действием и объектом. Связывай подписи с полями.
- Проверь порядок фокуса через `Tab` и `Shift+Tab`, видимость фокуса и активацию элементов с клавиатуры. Для согласованного перетаскивания предусматривай способ выполнить то же действие без жеста.
- Переиспользуй переменные цвета Obsidian. Проверь читаемость текста, диагностики и фокуса в светлой и тёмной теме.

## Списки и производительность

- Используй стабильные ключи, когда модель содержит устойчивый идентификатор. Учитывай, что порядок задач может измениться после перечитывания Markdown.
- Если спека предусматривает отдельную сортировку для экрана, сортируй копию массива. Используй `toSorted()`, когда его поддерживает целевая среда, или `[...items].sort(compare)`.
- Для многократного поиска по одному ключу в крупном наборе используй `Map`, если повторные обходы заметны при проверке. Строй индекс из текущей модели и пересоздавай его при смене данных.
- Добавляй мемоизацию или виртуализацию после измерения на списке, близком к рабочему.
