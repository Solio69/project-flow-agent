# Интерфейс Project Flow Agent

Адаптация [Senior Frontend 2.0.0](https://www.aitmpl.com/component/skills/development/senior-frontend) с дополнениями из Vercel React Best Practices. [Источники и лицензия](NOTICE.md).

## Перед реализацией

- Прочитай рабочий `spec.md`, критерии приёмки и конституцию. Проверь версии React и TypeScript, существующие компоненты, стили и команды проверки.
- Определи состояния, которые относятся к согласованному экрану. Для «Текущих действий» проверь, как выглядят обычный и пустой списки, недоступная заметка и частичный результат с диагностикой.

## Компоненты и данные

- Соблюдай границы проекта. `ItemView` подключает и освобождает React. Адаптер работает с Vault API и ссылками. Компоненты получают модель от ядра через вкладку и вызывают переданные обработчики.
- Вычисляй видимый список из модели и текущих фильтров при рендере. Храни в React состояние самого интерфейса. Используй эффекты для внешних подписок, освобождай ресурсы при закрытии и защищай обновления от запоздалого результата чтения.
- Переиспользуй компоненты проекта и CSS-переменные темы Obsidian. Ограничивай стили областью плагина. Используй семантические элементы, доступные имена действий и видимый фокус. Для деталей смотри [чек-лист интерфейса](references/ui-checklist.md).

## Проверка в Obsidian

- Запусти подходящие команды из плана фичи. Открой результат через обычный вход плагина. Для каркаса проверь открытие вкладки и появление пробной правки после Hot Reload.
- Для рабочего экрана пройди применимые состояния и действия в Obsidian. Проверь узкую и широкую панель, светлую и тёмную тему и переходы по интерактивным элементам с клавиатуры.
- Ошибки разбора и длинные данные проверяй на синтетических примерах. Первый просмотр в рабочем хранилище сохраняет Markdown без изменений. Действия с записью проверяй в пределах отдельной согласованной спеки.
- В `verification.md` укажи команды, реально пройденные сценарии в Obsidian и ограничения проверки.
