# Чек-лист ревью Project Flow Agent

Используй пункты, относящиеся к diff и согласованной фиче. Для каждой проблемы укажи конкретный сценарий сбоя.

## TypeScript и данные

- Значения `0`, пустые строки и отсутствующие поля могут требовать разной обработки. Проверяй, что `as` или `!` не обходят нужную проверку.
- Парсер извлекает поля из Markdown, Zod проверяет значения. Ошибка отдельного поля даёт диагностику. Проверь, что из-за неё не исчезают распознанные задачи.
- Сверь поддерживаемые форматы заметки со спекой. Проверь порядок проектов и задач, галочки, префикс действия рядом с `[[ссылкой]]` и обработку даты в шапке.
- Проверь, что при двух пересекающихся чтениях более старый ответ не затирает более свежий.

## Obsidian и React

- Сверь, что карточка проекта и его задачи в «Сегодня» используют одни
  настройки значка по пути заметки проекта. Проверь произвольный проект,
  псевдоним ссылки и запасной значок при недоступной конфигурации Iconize.

- Ядро работает с данными. Вызовы Vault API и работа со ссылками происходят в адаптере. `ItemView` связывает части, а React получает модель и обработчики.
- Проверь обновление при ручной правке исходной заметки, разрешение ссылок относительно исходного файла и освобождение подписок при закрытии вкладки или перезагрузке плагина.
- Проверь состояние React после повторного рендера и стабильность ключей при изменении порядка задач. Содержимое заметок отображается как данные.
- Для сохраняемого фильтра проверь оба положения на новом экземпляре плагина, порядок быстрых сохранений и отсутствие изменений в исходном Markdown.
- Для перетаскивания проверь пустое место, сдвиг при перекрытии более 30% соседней строки и отмену без записи. Захват за текст сохраняет обычное открытие ссылки по клику. Захват за ручку не перехватывает галочки и кнопки.
- После отпускания строки оставь указатель неподвижным и проверь, что подсветка исчезла. Следующее движение указателя возвращает её, а фокус клавиатуры остаётся видимым.
- В форме новой задачи сверяй значок проекта и подпись с макетом. При наличии кнопки закрытия начальный фокус должен попадать в поле названия в обеих темах.
- После подтверждения через Enter проверь переход фокуса на галочку созданной задачи. Для свёрнутой карточки проверь кнопку раскрытия, при отмене проверь возврат на «+».
- Первый просмотр «Текущих задач» работает в режиме чтения. Убедись, что открытие, обновление и навигация сохраняют рабочие файлы без изменений. Для согласованных фич с записью проверь конфликты, сохранение соседнего текста и поведение при частичном сбое.

## Проверки

- Сопоставь тесты с критериями приёмки. Тест должен упасть при возврате ошибки и проверять результат, который важен пользователю.
- Используй синтетический Markdown для пограничных случаев. Проверь, что тесты дат не зависят от текущего дня и часового пояса.
- Для проверок сборки и жизненного цикла используй команды из плана фичи. В отчёте отличай проверку кода от реально проверенного поведения в Obsidian.
