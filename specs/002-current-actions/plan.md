# План реализации просмотра текущих действий

**Ветка** `feature/add-current-action` · **Спека** [spec.md](spec.md)

## Подход

- `parse-current-actions.ts` принимает Markdown и возвращает период, группы,
  задачи и диагностику с номерами строк. Zod проверяет даты. Старый формат
  и формат со свойствами приводятся к общему представлению.
- Адаптер `obsidian-current-actions/` ищет точный файл у корня хранилища
  «Проекты» или в папке `Проекты/` объемлющего хранилища. Адаптер читает его
  через Vault API. Ссылки разрешаются относительно исходной заметки.
  Адаптер читает закрепление исходной вкладки при переходе через Workspace API.
  Закрепление, нажатие колёсиком или Ctrl/Cmd+клик открывают новую активную
  вкладку. При обычном переходе из незакреплённого списка используется
  исходная вкладка и её штатная история Obsidian.
  Для нового формата ID берётся из свойств связанной заметки. Проект
  строки «Сегодня» определяется по пути внутри известной папки.
  Функции адаптера и его константы лежат в одной папке. Общие операции
  Obsidian и его константы находятся в `src/obsidian/`.
- `ItemView` передаёт React состояние чтения и модель, подписывается на
  изменения файла и использует номер запроса, чтобы отсечь устаревшие
  результаты. Закрытие снимает подписки и освобождает React.
- `CurrentActions` отвечает за состояния экрана. `ActionsList`, `Task`
  и `NoteLink` отвечают за список, строку задачи и общий переход по ссылке
  задачи или проекта. Компоненты экспортируются через `index.ts` в своих
  папках. `src/styles.css` собирает стили компонентов в один файл для Obsidian.

## Проверка конституции

Данные берутся из Markdown. Ядро проверяется без Obsidian. Адаптер и
React остаются разделены. В рабочем хранилище используются чтение и
навигация. Этап согласования записи остаётся отдельным срезом.

## Последовательность проверок

1. Red → Green → Refactor для разбора двух форматов и диагностики.
2. Red → Green → Refactor для подключения модели, навигации, обновления
   и закрытия вкладки в имитации Obsidian.
3. `npm test` и `npm run build`. Сверка разбора актуальной заметки в режиме
   чтения. Результаты и доступность проверки в приложении записываются
   в `verification.md`.
4. Для ссылок задачи и проекта проверить новую активную вкладку из закреплённой
   вкладки и открытие в той же вкладке с возвратом через «Назад» из
   незакреплённой. Проверить смену режима закрепления, Ctrl/Cmd+клик
   и нажатие колёсиком.
5. После рефакторинга по кодстайлу прогнать разделённые интеграционные
   сценарии, тесты парсера и сборку. Сравнить результаты парсера и HTML
   компонентов до и после правок на одинаковых входных данных.
6. После переноса констант и стилей сравнить правила собранного CSS по
   селекторам. Проверить watch на временном хранилище, включая обновление
   сборки после правки компонента.
