# План реализации просмотра текущих задач

**Ветка** `feature/add-current-action` · **Спека** [spec.md](spec.md)

## Подход

- Перенос в «Сегодня» и обратно использует существующую защиту записи в
  `Vault.process()`. Адаптер разрешает файл задачи и заголовок проекта,
  выбирает место вставки по текущему снимку. Чистая операция удаляет одну
  исходную строку и вставляет её в целевом блоке. Два изменения сохраняются
  вместе. Внешние правки перечитываются после команды. Общая блокировка
  защищает команды отметки и переноса от пересечения в одной вкладке.

- Команда галочки сверяет снимок исходной заметки со свежим текстом внутри
  `Vault.process()`. Чистая операция использует границу блока из парсера,
  меняет отметку выбранной строки и сохраняет порядок активных и выполненных
  в этом блоке. Порядок остальных задач внутри каждой группы сохраняется.
  Новая выполненная становится первой среди выполненных, новая активная
  становится последней среди активных. Адаптер перечитывает ID
  связанных заметок для проверки дублей. При записи он повторно разрешает
  ссылки и сверяет версии файлов. Вкладка отключает галочки на время
  операции и показывает перечитанное состояние.
  Интеграционная проверка проходит через обычную регистрацию плагина.
  Проверить, что открытие вкладки только читает данные, а поставленная
  или снятая галочка сохраняется после её переоткрытия. В рабочем Obsidian
  проверить доступность галочек и оставить пользователю проверку записи.

- Собрать дизайн просмотра из React-компонентов экрана, панели периода,
  карточки со списком и строки задачи. Цветовые токены живут в CSS экрана,
  тема берётся из Obsidian, адаптация зависит от ширины самой вкладки.
  Иконки рисует Obsidian, акценты известных проектов заданы дизайн-системой.
  Оформление определяется по пути проектной заметки, псевдоним отображается
  в подписи. Группы классифицируются за один проход перед отрисовкой.
  Сворачивание и видимость выполненных принадлежат интерфейсу. Страница
  использует прозрачную внешнюю подложку, панель периода содержит общий
  переключатель. Списки отображают активные и выполненные в сохранённом
  относительном порядке. Источник Markdown и обработчик ссылок используют
  существующие контракты.

- Использовать `current-tasks` и `CurrentTasks` для исходников, компонентов
  и активной спеки. Сохранённый тип вкладки Obsidian остаётся стабильным.
  Адаптер ищет `Текущие задачи.md`, затем прежнее имя заметки. Проверить
  чтение и обновление после появления нового имени без записи в хранилище.

- `parse-current-tasks.ts` принимает Markdown и возвращает период, группы,
  задачи и диагностику с номерами строк. Zod проверяет даты. Старый формат
  и формат со свойствами приводятся к общему представлению.
- Адаптер `obsidian-current-tasks/` ищет точный файл у корня хранилища
  «Проекты» или в папке `Проекты/` объемлющего хранилища. Адаптер читает его
  через Vault API. Ссылки разрешаются относительно исходной заметки.
  Адаптер читает закрепление исходной вкладки при переходе через Workspace API.
  Закрепление, нажатие колёсиком или Ctrl/Cmd+клик открывают новую активную
  вкладку. При обычном переходе из незакреплённого списка используется
  исходная вкладка и её штатная история Obsidian.
  Для нового формата ID берётся из свойств связанной заметки. Проект
  строки «Сегодня» определяется по пути внутри известной папки.
  Функции адаптера и его константы лежат в одной папке. Общие операции
  Obsidian и его константы находятся в `src/obsidian/`.
- `ItemView` передаёт React состояние чтения и модель, подписывается на
  изменения файла и использует номер запроса, чтобы отсечь устаревшие
  результаты. Закрытие снимает подписки и освобождает React.
- `CurrentTasks` отвечает за состояния экрана. `TasksList`, `Task`
  и `NoteLink` отвечают за список, строку задачи и общий переход по ссылке
  задачи или проекта. Компоненты экспортируются через `index.ts` в своих
  папках. `src/styles.css` собирает стили компонентов в один файл для Obsidian.

## Проверка конституции

Данные берутся из Markdown. Ядро проверяется без Obsidian. Адаптер и
React остаются разделены. Согласованная запись галочки и позиции касается
одной заметки. Открытие, обновление и фильтрация используют чтение.

## Последовательность проверок

1. Red → Green → Refactor для разбора двух форматов и диагностики.
2. Red → Green → Refactor для подключения модели, навигации, обновления
   и закрытия вкладки в имитации Obsidian.
3. `npm test` и `npm run build`. Сверка разбора актуальной заметки в режиме
   чтения. Результаты и доступность проверки в приложении записываются
   в `verification.md`.
4. Для ссылок задачи и проекта проверить новую активную вкладку из закреплённой
   вкладки и открытие в той же вкладке с возвратом через «Назад» из
   незакреплённой. Проверить смену режима закрепления, Ctrl/Cmd+клик
   и нажатие колёсиком.
5. После рефакторинга по кодстайлу прогнать разделённые интеграционные
   сценарии, тесты парсера и сборку. Сравнить результаты парсера и HTML
   компонентов до и после правок на одинаковых входных данных.
   Сверить фиксированные атрибуты, переиспользование типов и формат
   комментариев по гайду проекта.
6. После переноса констант и стилей сравнить правила собранного CSS по
   селекторам. Проверить watch на временном хранилище, включая обновление
   сборки после правки компонента.
7. На синтетических заметках проверить поздний дубль ID, смену цели ссылки
   перед записью и повреждённый заголовок после корректного блока. Проверить
   оформление проекта с псевдонимом в карточке и в «Сегодня».
8. Red для галочек и фильтра должен показать, что прежний код сохраняет
   исходную позицию и показывает выполненные при выключенном переключателе.
   Green проверяет последовательные отметки, снятие, смешанный список,
   повторную команду, переоткрытие и отсутствие записи при фильтрации.
   После рефакторинга повторить `npm test` и `npm run build`, проверить
   прозрачный фон в обеих темах и видимость в рабочем Obsidian.
9. Red для переноса воспроизводит отсутствие подключённой команды и
   сохранения ожидаемого Markdown. Green проверяет вставку по проекту,
   добавление в конец активных, возврат, пустой блок и остановку при конфликте.
   Затем `npm test`, `npm run build` и проверка diff. Короткий чек-лист в
   Obsidian передаётся пользователю для ручной приёмки.
10. Для правки переключателя Red проверяет обе подписи и запрошенное ими
    изменение видимости. Green связывает подпись текущего действия с
    состоянием видимости. Интеграционная проверка сверяет подпись по умолчанию.
11. Проверить отказ при пересечении непустого текста между задачами или
   смене его соседей и сохранение галочки при неизменном соседстве.
   В Chromium проверить переход фокуса после скрытия выбранной строки
   и сохранение фильтра после ошибки чтения. Сверить общее объявление
   `TaskPeriod`, ключи списка, ручки активных задач и пустое состояние.
12. Проверить на синтетическом Markdown отказ без записи при комментарии
    перед задачей, повторном свойстве периода и смене второго проектного
    заголовка во время `Vault.process()`. В Chromium проверить восстановление
    фокуса при переносе, свёрнутой карточке, отказе и ручной смене фокуса.
    Проверить общий предикат, единый разделитель подписей и отсутствие лога
    в diff к `HEAD`. Результаты записать в `verification.md`.
13. Red для перестановки активных задач проверяет контракт записи через
    обычную вкладку на синтетическом Markdown. Green добавляет запись через
    существующий адаптер и жест в `TaskPanel`. Проверить порог 30%, отрисовку
    строки и пустого места, отмену и клавиатуру. Повторить `npm test`,
    `npm run build` и ревью, результаты добавить в `verification.md`.
14. При ревью перестановки проверить комментарий перед первой и после
    последней задачи. В изолированном браузере проверить отпускание за
    видимой границей прокручиваемого списка, Escape, состояние пустого
    места, порог сдвига и фокус ручки после записи и отказа.
15. Red для заголовка проверяет ссылку и открытие источника в новой
    активной вкладке. Для создания Red проверяет диалог, имя, содержимое
    исходника и новой заметки, повтор и частичный сбой. Green переиспользует
    открытие файла, добавляет диалог и две адресные проверки записи. До
    передачи повторить `npm test`, `npm run build` и проверку diff.
16. Проверить произвольный проект с эмодзи из существующих настроек, его
    карточку и префикс задачи в «Сегодня». Проверить значок папки при
    недоступных данных. Заявленный цвет использует существующую палитру.
17. При повторном ревью проверить смену проекта перед созданием, повтор
    при ссылке в другой группе и конфликт с неразрешённой ссылкой на
    заголовок. Для заметки проекта в корне проверить запасной значок.
    В Chromium проверить фокус и повторную отправку формы во время записи.
18. Проверить восстановление обоих положений переключателя новым экземпляром
    плагина. Хранить положение через API данных плагина в `data.json`.
    Проверить исходную заметку, соседние настройки и последнее положение
    при быстрых переключениях.
    При выносе констант проверить общий ключ чтения и записи, выбор
    значения по умолчанию и сохранение контракта `data.json` штатными тестами.
19. При упрощении однострочных обработчиков формы сверить сохранение
    порядка действий и возвращаемых значений. Повторить тесты и сборку.
20. После выноса строк `use-task-reorder` сверить имена событий, ключ проверки
    `pointerId` и формат CSS-сдвига. Повторить тесты и сборку, проверить
    отпускание и отмену перетаскивания в Chromium.
21. Выделить адаптер создания в папку `obsidian-current-tasks/create-task/`.
    Разделить выбор проекта и проверку снимка, координацию создания или
    повтора и запись ссылки через `Vault.process()`. Переиспользовать чтение
    ID и проверку источника в операциях записи. Сверить порядок проверок,
    частичный результат, повтор и публичный экспорт через действующие тесты.
22. Проверить в Chromium фокус после создания через Enter, в свёрнутом
    списке и после отмены. Для выбора новой строки использовать путь,
    подтверждённый успешной записью, в пределах карточки проекта.
