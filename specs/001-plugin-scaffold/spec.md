# Сделать сборку каркаса и подключить в Obsidian как плагин

**Ветка** `feature/plugin-scaffold`

**Карта проекта** «Текущие задачи», начало этапа «Запустить плагин и показать реальные задачи».

**Дата** 2026-11-23

**Статус** Объём согласован

## Согласованный объём и границы

Собрать React-каркас Project Flow Agent для установки в рабочем Obsidian.
На левой ленте появляется кнопка, которая открывает штатную вкладку
«Текущие задачи» в центральной области. Вкладка показывает заголовок
и статус каркаса. Агент проверяет сборку и автоматическое обновление
при пробной правке в режиме разработки.

Чтение и разбор заметки, показ задач, действия с задачами и согласование
дизайна относятся к следующим задачам. Этот срез работает с интерфейсом
Obsidian и файлами сборки в каталоге плагина.

## Пользовательские сценарии и проверки

### US1. Открыть каркас из Obsidian

1. После установки и включения плагина в Obsidian пользователь нажимает
   кнопку на левой ленте и видит вкладку «Текущие задачи».
2. Повторное нажатие открывает существующую вкладку этого типа, если она
   уже есть. После закрытия пользователь может открыть её снова.
3. Вкладка показывает заголовок и сообщает, что каркас запущен.
   Открытие и закрытие сохраняют содержимое Markdown без изменений.

### US2. Собрать и обновить плагин локально

1. Из чистой копии репозитория пользователь устанавливает зависимости
   из lock-файла и получает файлы плагина одной командой сборки.
2. В режиме разработки пользователь указывает рабочее хранилище. После
   правки интерфейса файлы плагина обновляются в его каталоге. При включённом
   Hot Reload новую версию можно увидеть в Obsidian без ручного переключения
   плагина.
3. Если путь к хранилищу неверен, команда сообщает об ошибке и завершает
   работу до записи файлов.
4. Из панели NPM Scripts в VS Code пользователь запускает `dev:obsidian`
   без аргументов. Путь к хранилищу берётся из локального файла.

## Требования

- **FR-001** Плагин регистрирует собственную вкладку и кнопку на ленте.
- **FR-002** Штатная вкладка подключает React при открытии и освобождает
  его при закрытии. Повторное нажатие на кнопку использует открытую вкладку.
- **FR-003** Сборка выпускает `manifest.json`, `main.js` и стили плагина.
- **FR-004** Режим разработки пересобирает плагин при изменении исходников.
  Для установки в хранилище он использует указанный каталог и маркер Hot Reload.
  Команда `dev:obsidian` читает путь из игнорируемого Git файла `.env.local`.
- **FR-005** Код просмотра сохраняет Markdown-файлы без изменений. Запись
  в режиме разработки ограничена файлами сборки в каталоге плагина.

## Критерии результата

- **SC-001** Проверки типов и сборка проходят. В каталоге сборки присутствуют
  три ожидаемых файла, а версия в манифесте совпадает с версией пакета.
- **SC-002** В Obsidian можно открыть и повторно активировать вкладку с ленты.
  Закрытие освобождает React, а новое открытие снова показывает каркас.
- **SC-003** В режиме разработки пробная правка попадает в новую сборку,
  которую Hot Reload подхватывает в рабочем Obsidian при включённом помощнике.
- **SC-004** Процедура установки и запуска описана для PowerShell. Результаты
  проверок указаны в `verification.md`.

## Предпосылки

- Для проверки доступна настольная версия Obsidian.
- Для автоматической перезагрузки в Obsidian включён отдельный плагин Hot Reload.
