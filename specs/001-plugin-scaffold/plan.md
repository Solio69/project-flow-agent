# План реализации каркаса плагина

**Ветка** `feature/plugin-scaffold` · **Дата** 2026-11-23 · **Спека** [spec.md](spec.md)

## Подход

- TypeScript в строгом режиме, Obsidian Plugin API и React. Вкладка подключает и освобождает React. Кнопка на ленте открывает вкладку в центральной области.
- esbuild собирает CommonJS с внешним модулем `obsidian`, манифест и CSS. Обычная сборка пишет в `dist/`. Режим `watch` с указанным хранилищем пишет туда в каталог плагина и добавляет маркер `.hotreload`.
- Скрипт `dev:obsidian` запускает тот же watch из панели NPM Scripts. Node.js загружает `PFA_OBSIDIAN_VAULT` из локального `.env.local`.
- В консольных проверках используем Node.js, npm и `node:test`. В интерфейсе применяем CSS-переменные темы. Проверку установленной версии проводим в Obsidian.
- Пользовательские данные и операции записи отсутствуют в каркасе. Модель задач и Zod относятся к следующему срезу просмотра.

## Проверка конституции

Границы ядра, адаптера и интерфейса соблюдены. В срезе меняется подключение плагина и вкладка. Markdown в рабочем хранилище остаётся источником данных для будущего просмотра. Автоматические проверки используют имитацию API Obsidian и временный каталог для сборки. Ветка и объём соответствуют `spec.md`.

## Структура

```text
src/main.ts                              регистрация плагина и открытие вкладки
src/current-actions/current-actions-view.tsx  ItemView и подключение React
src/current-actions/CurrentActions.tsx        содержимое каркаса
src/styles.css                           стили плагина
esbuild.config.mjs                       обычная сборка и watch
manifest.json                            метаданные плагина
tests/scaffold.test.mjs                  проверка поведения вкладки и сборки
```

## Проверки от теста к реализации

1. Red. Проверка подключения в имитации хоста должна сообщить, что кнопка и вкладка ещё не зарегистрированы. После реализации проверяем открытие, повторное нажатие и освобождение React при закрытии.
2. Green и Refactor. `npm test`, `npm run build` и проверка выходного набора. Временный каталог с `.obsidian` проверяет назначение файлов сборки, отказ для неверного пути и пересборку после пробной правки. Он используется только как файловая фикстура.
3. В Obsidian проверяем обычный вход с ленты, открытие и закрытие вкладки, видимую пробную правку после Hot Reload. Реально выполненное и оставшиеся ручные проверки указываем отдельно в `verification.md`.
